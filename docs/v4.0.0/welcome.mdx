**Aqua Protocol** is an open protocol for data accountability and provenance. It records data as **AquaTrees**: portable, cryptographically verifiable trees of revisions that can be exchanged across systems and checked by anyone who holds them — no central authority required.

<Callout type="warning" title="Experimental release">
Aqua Protocol v4 is under active development. The published components — <code>aqua-rs-sdk-core</code> and <code>aqua-template-registry</code> — are an early community release with a deliberately limited functionality scope. Version numbers have not yet been increased, backward compatibility is not yet provided, and breaking changes are expected and may occur without notice. The full <code>aqua-rs-sdk</code>, which extends this core, is scheduled for a later publication. For production use today, refer to the stable [v3 documentation](/docs/v3.0.2/introduction).
</Callout>

## What is Aqua Protocol?

The Aqua Protocol is a foundational framework for building distributed trust networks. By leveraging hash chains and cryptographic signatures, Aqua enables scalable, trustless verification of data integrity and provenance. It empowers developers and innovators to create applications that certify, attest, and secure data in an open and decentralized way.

Trust can be built by relying on hashing and signature mechanisms or by delegating to a mutually trusted party. Aqua Protocol handles both scenarios, giving you flexibility in how you establish and verify trust.

<Callout type="info" title="Powered by cryptography, not blockchain">
Aqua Protocol is made possible by crypto as in _cryptography_. The protocol neither is nor requires blockchain technology: records are secured by hash chains and digital signatures, and anyone holding the data can verify it independently.
</Callout>

## How it works

At its core, Aqua creates portable hash-linked structures called **AquaTrees** that record a gapless history of data revisions. Every revision is one of four kinds — **object** (typed data), **template** (the schema that defines a type), **signature** (a cryptographic endorsement), or **anchor** (a structural link between revisions and trees). Each revision references its predecessor by hash, so a modification anywhere in the history is immediately detectable.

AquaTrees are plain JSON. They can be stored, exchanged, and verified anywhere: verification is a local computation over the tree (and any trees it links to), not a call to a service.

Key capabilities of the v4 core profile:

- **Tamper-evident history** — every revision embeds the hash of its predecessor; changing any byte anywhere breaks the chain.
- **Typed data** — object revisions conform to templates (JSON Schema) identified by hash, so both sides of an exchange agree on structure.
- **Cryptographic signatures** — four suites: Ed25519, Ethereum EIP-191, ECDSA P-256, and WebAuthn P-256, with signer identities expressed as DIDs.
- **Selective disclosure** — tree-hashed revisions can be shared with individual fields redacted while the rest stays verifiable.
- **Portable verification** — trees are self-contained; the verifier needs the data, not an account on a platform.

The [Concepts](/docs/v4.0.0/concepts) page builds the full mental model; the [Schema Reference](/docs/v4.0.0/schema-reference/introduction) is the readable companion to the normative specification.

## What is available today

Two components are published, both under the Apache-2.0 license:

| Component | What it does |
|---|---|
| [`aqua-rs-sdk-core`](https://github.com/inblockio/aqua-rs-sdk-core) | The protocol core: anchor, object, and template primitives, four signature suites, selective disclosure, and the verification pipeline. Also home of the [protocol specification](https://github.com/inblockio/aqua-rs-sdk-core/tree/main/protocol-specification). |
| [`aqua-template-registry`](https://github.com/inblockio/aqua-template-registry) | Template distribution: publish, resolve, and subscribe to Aqua templates by publisher DID, as a Rust library and an HTTP service. A hosted instance runs at [aqua-registry.inblock.io](https://aqua-registry.inblock.io), provided without SLA. |

Neither crate is on crates.io yet (publication is planned). Install the core as a git dependency:

```toml
[dependencies]
aqua-rs-sdk-core = { git = "https://github.com/inblockio/aqua-rs-sdk-core" }
```

[Release Status & Versioning](/docs/v4.0.0/version-info) states exactly what this release contains, what it deliberately excludes, and which stability guarantees apply.

## Why Aqua

**Proof, not platforms.** Records are secured by hash chains and cryptographic signatures. Verification requires no blockchain and no central authority: anyone holding the data can check it independently.

**Provenance that travels.** Every revision links to the one before it, forming a portable, gapless history of origin and change. Integrity stays checkable wherever the data goes.

**Open by design.** An open standard with open-source implementations. Only hashes ever need to leave your hands, so the data itself stays private and under your control.

## Aqua v3 (stable)

Aqua Protocol v3 is the stable, production-ready release, built around a JavaScript/TypeScript SDK. If you are building for production today, start with the [v3 documentation](/docs/v3.0.2/introduction). The v4 release documented here is the experimental successor and does not yet replace it.
